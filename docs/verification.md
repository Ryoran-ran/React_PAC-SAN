# Phase 1–3とPhase 4一部の検証記録

## Phase 4の部分実装（2026-10-18）

原作の曲がり角の先行・遅延ターンを整数ピクセルの斜め補正で実装しました。曲がりながら通過するタイルのドット取得と、ゴーストハウスのゲートをピンクに保つ面クリア時の白い壁点滅を確認しました。資料は [The Pac-Man Dossier](https://cs.au.dk/~ocaprani/GameAI/PacMan/The%20Pac-Man%20Dossier.pdf) の Cornering 節を参照しています。

Vitest 20ファイル・116テスト、TypeScript型チェック、本番ビルドが成功しました。長時間のTASテストも従来の到達条件を満たしています。

ゴースト個別・全体カウンタと1フレーム1回の接触判定も試しましたが、既存のTAS長時間テストでゲームオーバーまで退行したため採用を保留しました。両者を変更するときは、自動操作の巣退出予測と接触予測を同時に調整する必要があります。

検証日：2026-10-17（日本時間）。対象：v0.3.1 / Phase 1基盤・Phase 2ゴーストAI・デバッグ用オートプレイ・Phase 3ゲーム進行。

### テストが保証する範囲

- 迷路28×31、通常ドット240・パワー4、合計2600点、4隅のパワー配置。
- 開始位置から全ドットへ到達可能。ハウス・ゲート・外側空間への進入不可。
- 壁での停止、方向予約、ブロックされた入力の保持、中心間での即時反転、両方向のトンネル接続。
- 10 / 50点加算、取得したドットの一度限りの消費、1 / 3フレームの厳密な停止と移動再開。
- TITLE / READY / PLAYING、READY中の停止・再開、PLAYING中の再開始防止。
- 実際に迷路を移動して全244個を回収し、ドット由来の2600点以上でLEVEL_CLEARへ到達。演出中は移動を止め、次の面で迷路と設定を初期化。
- 同一入力を2000フレーム再生した際の内部状態・残存ドットの一致。デバッグのON / OFFがロジックへ影響しないこと。
- 描画30 / 60 / 120 / 144 Hzの各条件で10秒間に600回更新。フレーム落ち時の時間保持、catch-up上限後の未処理時間保持、非アクティブ復帰時の時計リセット。
- ハイスコアの正常な保存・読み込み、不正データの無視、保存拒否・容量不足でも例外がプレイへ伝播しないこと。
- 赤・ピンク・水色・オレンジのターゲット計算。上向き時に生じるピンクと水色の原作由来オフセットを含む。
- 交差点で反対方向を候補から外し、同距離を上・左・下・右の順で決定。4地点の上方向禁止。
- SCATTER / CHASEの切替フレーム、最終CHASEの継続、リセット。モード切替後、次のタイル中心で行う強制反転。
- ピンク、水色、オレンジの順序、30・60ドット条件と無取得タイマーによる巣からの退出。
- 5000フレームの決定的な連続更新で、全ゴーストが整数座標を保ち、巣外のタイル中心が常に通路上にあること。
- 初心者とTASで敵付近の進路が変わること。4段階すべてで全244ドットを回収し、2600点以上でクリアできること。
- 同じ状態からTAS段階を再生したときの状態一致。手動入力とF3終了で自動操作が解除されること。

## ブラウザー上の動作確認

Chromeで `http://127.0.0.1:5173/` を開き、以下を確認しました。

- 黒地・青い迷路・ドット・パワーエサ・黄色いプレイヤー・スコアが描画される。
- Enterで開始し、READY後に左移動とドット取得を行う。取得数とスコアが更新され、取得済みドットが消える。
- Pで一時停止。検証中のフレーム356・座標(52,188)が後続の観測でも固定される。
- 停止中に上入力を予約し、Pで再開すると上方向へ移動する。
- F3でデバッグパネルと通行可能グリッド・当たり判定中心が表示される。
- 画面内の一時停止ボタンで停止。Dキーの予約がデバッグ表示の `up / right` に反映される。
- ページ再読込後も、検証中に取得したハイスコア290がCanvasに残る。
- 通常のデスクトップ表示では448×576（2倍）。390×844の狭い画面では224×288（1倍）で表示し、操作欄が下へ移る。横方向のページはみ出しなし。検証後はブラウザーの表示サイズ設定を元に戻した。
- ブラウザーの警告・エラーログなし。

## スクロール不要の配置への更新（2026-10-17）

ユーザーの要望により、画面全体の高さをブラウザーの表示領域に合わせました。Canvasの倍率は親領域の実測幅・高さから決定します。整数倍を優先し、1倍でも収まらない小型画面のみ全体を縮小します。右側の通常情報は上端へ寄せ、デスクトップではデバッグパネルをその下の空き領域へ表示します。狭い画面では配置を崩さないため重ねて表示し、どちらにも閉じるボタンを設けています。

Chromeで1920×911、1366×768、1024×600、390×844、320×568、844×390を確認しました。各サイズでページの幅・高さが表示領域と一致し、Canvas全体とすべての操作ボタンが領域内に収まることをDOMの寸法と画面で確認しています。1366×768では448×576の2倍表示、320×568では約198×255への縮小表示です。320×568と1366×768ではデバッグパネルも表示領域内に収まり、閉じるボタンで戻れることを確認しました。更新後の型チェック・本番ビルドも成功しました。

初回の動作確認に記載したスマートフォンでの縦配置と整数倍固定は、この更新に置き換わります。

## Phase 3の検証（2026-10-17）

自動テストでは、パワーエサ後の恐怖時間とモードタイマー停止、恐怖時間のない後半面での接触、ゴースト2体の連続捕食得点と帰還・復帰、通常接触での死亡と得点・ドット保持、最終残機後のゲームオーバーと再開、1万点の追加残機、70・170ドットでのフルーツ出現・回収・時間切れ、クリア演出後の次面移行、乱数の再現性を確認しました。既存の迷路・ゴーストAI・4段階オートプレイのテストもすべて成功しています。

後半面の2ピクセル移動で、更新途中に通常ドットやパワーエサの中心を通過した場合も、その場で取得・得点・移動停止・恐怖モード開始が行われる回帰テストを追加しました。修正前は通常ドットのテストで244個のままになり、修正後は243個になっています。ドット取得済みの曲がり角を途中で通過しても、オートプレイがその中心で進路を選べることも確認しました。

Chromeで新規ゲームを開き、残機・フルーツ・恐怖時間・ゴースト状態を通常表示とF3表示で確認しました。デバッグ表示を開いた状態で1366×768、320×568、844×390のページ寸法が表示領域と一致し、横・縦スクロールが発生しないことを確認しました。TAS自動操作でドットが進み、通常のゴースト接触が有効な状態でもブラウザーの警告・エラーログはありませんでした。
